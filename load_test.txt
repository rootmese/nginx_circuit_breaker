LOAD TESTING REPORT - traction_control module v0.4.1-beta
============================================================

This document summarizes load tests performed to validate:
- Behavior under extreme stress conditions
- Automatic state transitions
- Progressive degradation and recovery mechanism

------------------------------------------------------------
TEST ENVIRONMENT
------------------------------------------------------------

Platform        : WSL (Windows Subsystem for Linux)
Nginx Version   : 1.31.1 - 6.6.114.1-microsoft-standard-WSL2 (OpenSuse)
Backend         : HTTP service on 127.0.0.1:8080
Load Generator  : wrk (HTTP benchmarking tool)
Duration        : 120 seconds per test

------------------------------------------------------------
STRESS CONFIGURATION (IMPORTANT NOTE)
------------------------------------------------------------

The following configuration values were intentionally used
to force the module into high-stress and degradation scenarios.

These parameters are NOT representative of production usage.

They were chosen specifically to:

- Maximize backend pressure
- Trigger error rate escalation
- Validate state transitions under extreme load
- Observe recovery behavior under non-linear failure conditions

Load parameters:
- 1500 concurrent connections
- 18 threads
- Aggressive backend timeouts (2–5 seconds)
- High contention HTTP workload via wrk

------------------------------------------------------------
CONFIGURATION B (CHAOTIC / AGGRESSIVE)
------------------------------------------------------------

proxy_connect_timeout 2s;
proxy_read_timeout    5s;
proxy_send_timeout    5s;

traction_warning_threshold   95;
traction_critical_threshold  80;
traction_emergency_threshold 60;

traction_warning_action rate_limit=30%;
